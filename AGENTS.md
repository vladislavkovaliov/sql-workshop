# sql-workshop — agent instructions

## Project structure

This is a Go educational backend for a SQL workshop. Module name: `shop-api` (Go 1.25).

```
backend/
  cmd/api/main.go              — entrypoint
  internal/config/config.go    — env-based config (godotenv)
  domain/product/              — Product entity + Repository interface
  repository/product/          — repository implementation (empty)
  service/product/             — business logic (empty stub)
  http/handlers/product.go     — Gin handler (imports service, not wired)
  http/dto/product.go          — response DTO
  docs/                        — swaggo generated (regenerated by Air)
  .air.toml                    — hot-reload config
```

## Key conventions

- **Architecture**: domain → repository → service → handler (clean layers, DIP via interfaces in domain)
- **Repository interface** lives in `domain/product/repository.go`, impl goes in `repository/product/`
- **Package naming**: service package is `service/product/` (package `product`), handler package is `http/handlers/` (package `handlers`)
- **Domain fields are Unexported lowercase** — intentional (project style); serialization uses explicit mapping in DTOs
- **DTO fields must be Exported** to work with `encoding/json` — current `ProductResponse` has lowercase fields, which is a bug (json tags won't help if field is unexported)

## Commands

| Action | Command |
|--------|---------|
| Run with hot-reload | `air` (from `backend/`) |
| Manual build | `go build -o ./tmp/main ./cmd/api/main.go` |
| Run directly | `go run ./cmd/api/main.go` |
| Regenerate swagger | `swag init -g ./cmd/api/main.go` |
| Run tests | `go test ./...` |

## Database

- Default URL: `postgres://postgres:postgres@localhost:55000/shop`
- Config via env vars: `PORT`, `DATABASE_URL` (loaded from `.env` if present)
- No Docker setup in repo — Postgres expected externally (see `scripts/` for SQL)
